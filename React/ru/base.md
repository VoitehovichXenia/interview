# Что такое React?

**React** - JS Библиотека для построения UI с декларативным подходом и компонентной архитектурой.

# Разница между React и ReactDOM?

**React** — это основная библиотека для создания UI-компонентов и управления их логикой, работающая с Virtual DOM.

**ReactDOM** — это отдельная библиотека-рендерер, которая переносит эти компоненты в реальный DOM браузера, отвечая за отрисовку и обновления

# Особенности React

1. **Декларативность** 
2. **Компонентный подход**
3. **Virtual DOM**
4. **Однонаправленный поток данных**
5. **Hooks** (это функции, представленные в React 16.8, позволяющие использовать состояние (state), методы жизненного цикла и другие возможности React в функциональных компонентах без написания классов)
6. **SSR/CSR** поддержка

Преимущества React:

- **Компонентный подход** - упрощает разработку и поддержку кода, обеспечивает переиспользуемость а также скорость разработки
- **Virtual DOM** - копия реального DOM, так как прямые изменения DOM очень дорогостоящие, React применяет изменения сначала в Virtual DOM, а затем точечно переносит в реальный DOM только измененные узлы, не обновляя страницу целиком.
- **Декларативный стиль** - упрощает написание кода и делает его более предсказуемым (описывае ЧТО хотим получить, а именно как интерфейс должен выглядеть в разных состояниях, а не КАК мы это будем делать).
- **Кроссплатформенность (React Native)** - возможность создавать кроссплатформенные мобильные приложения (iOS и Android) с использованием того же кода.
- **Огромная экосистема и комьюнити** - много готовых библиотек, инструментов, документации и активное сообщество разработчиков.

# Является ли React реактивным?

**Реактивность** - это парадигма программирования, ориентированная на автоматическое распространение изменений. В программировании эта идея чаще всего реализуется через потоки данных (streams) — асинхронные последовательности событий, которые происходят во времени. На эти потоки можно подписываться и реагировать на них.

Пример: электронная таблица. Вы меняете значение в одной ячейке, и все ячейки, которые от неё зависят, мгновенно пересчитываются. Им не нужно давать команду «обновись!», они сами реагируют на изменение источника данных.

**React реактивен**, да, но он реализует свою, особую модель реактивности (в отличие от Vue и RxJS)

- UI автоматически реагирует на изменения данных.
- Однако React не является «реактивным» в классическом смысле, т.к.не предоставляет из коробки мощных инструментов для управления потоками событий. Его реактивность узко специализирована и нацелена на одну задачу: эффективное обновление дерева компонентов.
- React использует pull-based модель с планированием обновлений, идеально заточенную под задачи построения пользовательских интерфейсов. Именно поэтому для сложных сценариев управления асинхронными потоками (например, при работе с WebSockets или сложными анимациями) разработчики часто комбинируют React с библиотеками вроде RxJS, получая лучшее из двух миров.

# Разница между теневым (Shadow) и виртуальным (Virtual) DOM?

- **Shadow DOM** обеспечивает инкапсуляцию стилей и структуры компонентов (изолированное поддерево)
- **Virtual DOM** оптимизирует производительность обновления интерфейса, создавая легкую копию реального DOM в памяти.

**Shadow DOM:**
- Обеспечивает **инкапсуляцию** стилей и структуры компонентов (изолированное поддерево). Cтили внутри Shadow DOM не влияют на внешнюю страницу, и наоборот.
- Нативно поддерживается браузерами, присоединяется к реальному DOM-элементу.
- Создание изолированных веб-компонентов.

**Virtual DOM:**
- Оптимизирует **производительность** обновления интерфейса, создавая легкую копию реального DOM в памяти, изменения сначала вносятся в VDOM, затем React находит разницу (diffing) и применяет только необходимые изменения к реальному DOM.
- В оперативной памяти, реализуется JS-библиотеками, нативно не поддерживается.
- Эффективное обновление интерфейса в SPA (Single Page Applications).

# Что такое JSX?

**JSX** - это расширение языка JavaScript (JS + XML-подобный синтаксис). Используется для удобной реализации декларативного стиля в React. С помощью него разработчик описывает как должен выглядеть UI.

## Разница JSX vs HTML

### JSX

- синтаксическое расширение JS, использующееся для того чтобы разработчик передал React информацию об UI компонента
- возможна вставка JS (выражения, camelCase, className)
- не интерпретируется браузером напрямую, должен быть скомпилирован в нативный JS
- файлы содержащие JSX имеют ``.jsx`` расширение

### HTML

- разметка страницы, содержащая информацию об элементах на странице
- интерпретируется браузером напрямую
- файлы содержащие HTML имеют ``.html`` расширение

# Reconciliation

**Reconciliation** (согласование) - алгоритм сравнения осуществляющий процесс обновления виртуального DOM, при котором React определяет, какие части интерфейса нужно изменить в реальном DOM, а что оставить без изменений. React сравнивает деревья нового виртуального DOM с предыдущим, начиная с их корневых элементов и направляется вниз.

- Если элементы различных типов
    Старый узел удаляется вместе со всеми дочерними узлами
    Создается новый узел со всеми дочерними элементами
- Если элементы одного типа
    Узел сохраняется 
    Сравниваются только атрибуты обоих, при этом обновляются только изменённые атрибуты. Обновляя ``style``, обновляются только изменившиеся свойства. 
    После обработки узла, React рекурсивно проходит также по дочерним элементам
- Компоненты одного типа
    Экземпляр сохраняется, поэтому его состояние сохраняется между рендерами
    React обновляет пропсы базового экземпляра компонента для соответствия новому элементу и вызывает componentWillReceiveProps(), componentWillUpdate и componentDidUpdate() на базовом экземпляре.
- Рекурсия по дочерним элементам
    При рекурсивном обходе дочерних элементов узла React одновременно проходит по обоим спискам потомков и создаёт мутацию, когда находит отличие.

## Ключи

При изменении компонента (вставке нового дочернего элемента в начало), React будет мутировать каждого потомка, вызывая лишние рендеры

```jsx
<ul>
  <li>New York</li>
  <li>Los Angeles</li>
</ul>

<ul>
  <li>Seattle</li>
  <li>New York</li> {/* Будет полностью перерендерен */}
  <li>Los Angeles</li> {/* Будет полностью перерендерен */}
</ul>
```

Для избежания такого поведения стоит использовать ключи.

**Ключ (key)** - уникальный идентификатор, позволяющий React отслеживать произошли ли изменения в дочених узлах или нет. Когда у дочерних элементов есть ключи, React воспользуется ими, чтобы сопоставить потомков исходного дерева с потомками последующего дерева.

Ключ должен быть уникальным только среди его соседей, а не глобально.

# React Fiber

Старый React (stack reconciler):
- работал синхронно
- не мог прерывать длинные обновления
- блокировал основной поток => снижение фреймрейта (лаги UI)

Существовала проблема: если дерево большое, пользовательский ввод "фризится". Fiber решает это.

Основные концепции:
- Fiber = единица работы
    Каждый компонент превращается в fiber-узел (объект), при этом превращая "дерево" Virtual DOM в связанный список (linked list)
    ```jsx
    {
      type,
      stateNode,
      child,
      sibling,
      return,
      pendingProps,
      memoizedProps,
    }
    ```
- Двухфазный рендеринг
    - Render phase (reconciliation)
        вычисляется новое дерево
        можно прерывать
        НЕ трогает DOM
    - Commit phase
        применяются изменения в DOM
        синхронная (непрерываемая)
- Приоритеты (Scheduling)
    Fiber делит задачи на приоритеты:
    - High (input, клики)
    - Medium (анимации)
    - Low (background обновления)
- Time slicing
    React может:
    - выполнить часть работы
    - отдать управление браузеру
    - продолжить позже
- Concurrent rendering (настраиваемый)
    рендеринг может быть прерван
    React может "передумать» и начать заново

## Как работает Fiber (упрощённо)

1. Создаётся новое дерево Fiber
2. React проходит его (DFS)
    Для каждого узла:
      - вычисляет изменения
      - создаёт эффекты (собирает список изменений)
          - вставка
          - обновление
          - удаление
      - коммит изменений в DOM

Примеры возможностей Fiber - [React Suspense](#что-такое-react-suspense)

# Что такое "Hydration" в контексте серверного-рендеренга React-приложений?

**Hydration** - это процесс «оживления» статического HTML-кода, присланного сервером, клиентским JavaScript-фреймворком (React, Vue, Angular). SSR.

# Что такое портал (Portal)?

**React Portal** - это механизм, позволяющий рендерить дочерние компоненты в DOM-узел, находящийся вне иерархии родительского компонента

```jsx
// Классовые компоненты
ReactDOM.createPortal(child, container).

// Функциональные компоненты
import { createPortal } from 'react-dom';
// ...
<div>
  <p>This child is placed in the parent div.</p>
  {createPortal(
    <p>This child is placed in the document body.</p>,
    document.body
  )}
</div>
```

# Что такое фрагмент (Fragment)? Почему фрагмент лучше, чем div?

**React Fragment** - нужен для группировки списка дочерних элементов (JSX) без создания лишнего узла в DOM-дереве (лучше чем div т.к. нет лишней вложенности, которая негативно влияет на Layout фазу рендера HTML страницы).

# Что такое синтетические события в React (SyntheticEvent)?

**SyntheticEvent** - React обёртка над нативными событиями.

- обеспечивает кроссбраузерность
- производительны, т.к. React не привязывает обработчики событий к каждому узлу DOM. Вместо этого он использует один обработчик событий на уровне корня приложения (делегирование событий).
- имеют тот же интерфейс, что и нативные события, включая методы stopPropagation() и preventDefault().
- предоставляет доступ к NativeEvent (e.nativeEvent)

# Что такое события указателя (Pointer Events)?

**Pointer Events** унифицированные события для мыши/тача/стилуса.

# Что такое контекст (Context)?

**React Context** - встроенный в React механизм (интерфейс), предназначенный для передачи данных (состояний, функций) от родительского компонента к глубоко вложенным дочерним компонентам без необходимости явной передачи пропсов (props) через каждый уровень дерева компонентов

```jsx
const Context = React.createContext(null);

// Классовые компоненты
class MyClass extends React.Component {
  render() {
    let value = this.context;
    /* отрендерить что-то, используя значение Context */
  }
}
MyClass.contextType = Context;

// Функциональные компоненты
export function useContext() {
  const context = React.useContext(Context);
  if (!context) throw new Error('Use app context within provider!');
  return context;
}

export const ComponentProvider = ({ children, ...props }) => {
  const context = useContext(props);
  return <Context.Provider value={context}>{children}</Context.Provider>;
};
```

# Что такое React-ссылка (ref)?

**React-ссылка (ref)** — это механизм в React, позволяющий получить прямой доступ к DOM-узлу (элементу HTML) или экземпляру компонента, созданного в методе рендеринга

Ключевые особенности refs:
- сохраняет значения между повторными рендерами
- изменение ref.current не вызывает повторный рендер компонента
- применяется для фокуса элементов, выделения текста, управления воспроизведением медиа, интеграции с библиотеками сторонних производителей

# Как создать ссылку (ref)?

Ref можно создать с помощью:
- ``useRef()`` - функциональные компоненты
- ``React.createRef()`` - классовые компоненты
- ``Callback refs`` - можно передать функцию в атрибут ``ref``, которая получает DOM-элемент в качестве аргумента.

Шаги создания:
- Создать ссылку внутри компонента: const ``myRef = useRef(null);``.
- Привязать ссылку к элементу через атрибут ``ref={myRef}``.

# Что такое условный рендеринг (Conditional Rendering)? Как его выполнить?

**Условный рендеринг (Conditional Rendering)** — это процесс отображения различных элементов интерфейса (компонентов) в React в зависимости от заданных условий, таких как состояние (state), пропсы (props) или данные пользователя.

# Что такое строгий режим в React? Его преимущества?

**React StrictMode** — это инструмент разработки, который подсвечивает потенциальные проблемы в приложении, активируя дополнительные проверки и предупреждения для потомков. Он не рендерит видимого UI и не влияет на продакшн, помогая находить ошибки жизненного цикла, небезопасные методы и устаревшие API.

React намеренно вызывает некоторые методы (например, constructor, render, shouldComponentUpdate) **дважды**, чтобы заметить нежелательные побочные эффекты (side effects).

На данный момент StrictMode помогает в:
- Обнаружении **небезопасных методов жизненного цикла**
- Предупреждении об использовании **устаревшего API** строковых реф, контекста
- Предупреждении об использовании устаревшего метода **findDOMNode**
- Обнаружении **неожиданных побочных эффектов**
- Обеспечение **переиспользованного** состояния

StrictMode рекомендуется использовать во всем приложении, обернув корневой компонент в ``<React.StrictMode>``

# Что такое «опрос» (Polling)? Как его реализовать в React?

Polling — это метод синхронизации данных, при котором клиент (React-приложение) через заданные промежутки времени автоматически отправляет запросы на сервер, проверяя наличие обновлений. В React это реализуется через useEffect и setInterval (короткий опрос) или рекурсивный setTimeout (длинный опрос) для автоматического получения свежих данных без участия пользователя.

## Короткий опрос (Short Polling) с setInterval

```jsx
import { useEffect, useState } from 'react';

function DataFetcher() {
  const [data, setData] = useState(null);

  useEffect(() => {
    // Функция получения данных
    const fetchData = async () => {
      const response = await fetch('/api/data');
      const result = await response.json();
      setData(result);
    };

    // Запрос при монтировании
    fetchData();

    // Запрос каждые 5 секунд
    const interval = setInterval(fetchData, 5000);

    // Очистка интервала при размонтировании
    return () => clearInterval(interval);
  }, []);

  return <div>{JSON.stringify(data)}</div>;
}
```

## Длинный опрос (Long Polling) с setTimeout

При длинном опросе клиент отправляет запрос, а сервер держит его открытым, пока не появятся новые данные, или пока не истечет таймаут. Это эффективнее, чем setInterval. 

```jsx
useEffect(() => {
  let timerId;
  const fetchData = async () => {
    try {
      const response = await fetch('/api/long-poll');
      const result = await response.json();
      setData(result);
    } catch (e) {
      console.error(e);
    } finally {
      // Следующий запрос только после завершения текущего
      timerId = setTimeout(fetchData, 1000); 
    }
  };

  fetchData();

  return () => clearTimeout(timerId); // Очистка
}, []);
```

Альтернативы: WebSockets (двунаправленное соединение) или Server-Sent Events (SSE) (технология, позволяющая серверу автоматически отправлять обновления данных на веб-страницу (клиенту) в реальном времени через долгоживущее HTTP-соединение. В отличие от WebSockets, это односторонний канал (только сервер -> клиент), что делает SSE простым и легким решением для лент новостей, графиков и уведомлений)

# Что такое ReactDOMServer?

ReactDOMServer — это объект (API) в React, используемый для рендеринга компонентов в статический HTML на стороне сервера (Node.js). 

# Что такое предохранители (Error Boundaries)?

Предохранители — это компоненты React, которые отлавливают ошибки JavaScript в любом месте деревьев их дочерних компонентов, сохраняют их в журнале ошибок и выводят запасной UI вместо рухнувшего дерева компонентов.

Классовый компонент является предохранителем, если он включает хотя бы один из следующих методов жизненного цикла static getDerivedStateFromError() или componentDidCatch(). 

# Что такое «ленивая» (Lazy) функция?

позволяет отложить загрузку кода компонента до его первого рендеринга.

Это уменьшает начальный размер бандла приложения, так как код компонента загружается «по запросу», а не при старте, что улучшает производительность. Используется вместе с Suspense для отображения загрузчика

# Что такое React suspense

React Suspense - это компонент React, позволяющий «приостановить» рендеринг части интерфейса до тех пор, пока не будут выполнены определенные условия (например, загрузка данных, кода или изображений). Он автоматически отображает резервный контент (спиннер или текст) в момент ожидания, обеспечивая декларативное управление состояниями загрузки

```jsx
import React, { Suspense } from 'react';
const LazyComponent = React.lazy(() => import('./MyComponent'));

function App() {
  return (
    <Suspense fallback={<div>Загрузка...</div>}>
      <LazyComponent />
    </Suspense>
  );
}
```

# Как в React реализовать двустороннее связывание данных?

1. Контролируемые компоненты (useState для хранения значения и onChange для его обновления)
2. Двустороннее связывание между компонентами (передача состояния (state) и функцию его обновления (setState) от родителя к дочернему компоненту через пропсы)
```jsx
const [name, setName] = useState('')

render () {
  <InputChild value={name} onValueChange={setName} />
}
```
3. Использование кастомных хуков (например для обработки множества полей формы можно создать кастомный хук, который возвращает текущее значение и функцию его изменения)


# Разница между useEffect() и componentDidMount()?

componentDidMount() - вызывается 1 раз после mounting
useEffect(callback, [dependencies]) - вызывается после mounting и после каждого update (componentDidMount + componentDidUpdate)

# Преимущества хуков

- Упрощение переиспользования логики: Кастомные хуки позволяют выносить логику состояния из компонентов и переиспользовать ее, избегая сложной иерархии HOC (Higher-Order Components) или render props.
- Лаконичный код: Функциональные компоненты с хуками обычно занимают меньше строк, чем аналогичные классовые компоненты, так как не требуют конструкторов, this и методов жизненного цикла.
- Лучшая читаемость: Логика, связанная с одной функцией (например, подписка и отписка), находится в одном месте (useEffect), а не размазана по componentDidMount и componentWillUnmount.
- Отказ от this: Избавляет от путаницы с привязкой контекста this в JavaScript. 

# Недостатки хуков:

- Строгие правила (Rules of Hooks): Хуки должны вызываться только на верхнем уровне, их нельзя вызывать внутри циклов, условий или вложенных функций.
- Сложность с замыканиями (Closures): Эффекты и колбэки "захватывают" старые значения (state/props), что часто приводит к устаревшим данным, если не указать правильные зависимости.
- Сложные массивы зависимостей: Управление зависимостями в useEffect, useCallback, useMemo может быть утомительным и вызывать бесконечные циклы рендера при ошибках.
- Трудности при переходе с классов: Разработчикам, привыкшим к явному жизненному циклу, сложно переключиться на декларативный подход хуков.

# Flux архитектура

Архитектура Flux - это паттерн управления состоянием, разработанный Facebook для создания масштабируемых и управляемых приложений на React. Он был создан в ответ на проблемы, возникающие при управлении состоянием в сложных приложениях.

Основные компоненты архитектуры Flux:

1. Действия (Actions): Действия представляют собой объекты, которые описывают события или изменения, происходящие в приложении. Они инициируются различными событиями, такими как пользовательские действия, сетевые ответы и т. д. Действия содержат информацию о типе события и необходимых данных для обработки этого события.

2. Диспетчер (Dispatcher): Диспетчер является центральным хабом в архитектуре Flux. Он принимает действия и передает их зарегистрированным обработчикам (stores). Диспетчер также гарантирует, что действия обрабатываются последовательно и синхронно, что позволяет избежать состояния гонки.

3. Хранилища (Stores): Хранилища содержат состояние приложения и логику его обновления. Они реагируют на действия, обновляют состояние и уведомляют своих подписчиков о изменениях. Каждое хранилище отвечает за управление определенной частью данных приложения и имеет строгую структуру состояния.

4. Представления (Views): Представления (компоненты) React отображают состояние приложения и реагируют на его изменения. Они подписываются на хранилища для получения обновлений и перерисовки себя при изменении состояния. Представления также инициируют действия при пользовательском взаимодействии.

5. Единство данных (Unidirectional Data Flow): Flux использует однонаправленный поток данных, где изменения состояния могут происходить только путем действий, передаваемых через диспетчер и обрабатываемых хранилищами. Это упрощает отслеживание и отладку потоков данных в приложении.

Преимущества Flux:

Четкая структура: Flux обеспечивает четкую организацию кода и распределение ответственности между различными компонентами.

Отсутствие зависимостей: Компоненты в Flux взаимодействуют друг с другом через действия и хранилища, что позволяет избежать сложностей связанности.

Легкая отладка: Однонаправленный поток данных и строгий контроль изменения состояния упрощают обнаружение и исправление ошибок в коде.

# Что такое useReducer()?

хук возвращает массив с двумя элементами. Первый элемент массива - состояние, второй элемент - функция изменения состояния. Классически именуют так:

store либо state (состояние)

dispatch (функция изменения состояния)

const [store, dispatch] = useReducer(...);

Когда использовать useReducer
Не существует строгого правила, когда нужно использовать useState, а когда useReducer. Но есть некоторые признаки, по которым можно понять, что стоит попробовать useReducer.

Когда в компоненте есть несколько useState, в целях оптимизации можно заменить их единственным useReducer. Меньше хуков, меньше затрат памяти, больше производительность. Однако это зависит от приоритетов. useReducer может потребовать написать много action и это может негативно сказаться на читабельности кода.

Если одно состояние зависит от другого, это с большой вероятностью работа для useReducer. Все зависимости одного состояния от другого лучше описывать в редукторе (reducer)

# Расскажите о хуках useCallback(), useMemo(), useImperativeHandle(), useLayoutEffect()?

useCallback()

Что делает:
Мемоизирует функцию, чтобы её ссылка не менялась между рендерами.

const handleClick = useCallback(() => {
  doSomething(value);
}, [value]);

Зачем:

предотвращает лишние ререндеры дочерних компонентов (React.memo)
стабилизирует зависимости в useEffect

Когда нужен:

передаёшь callback в memo-компоненты
функция в dependency array

Важно:

сам по себе не ускоряет — может даже замедлить (из-за overhead)
нужен только если есть referential equality проблема

useMemo()

Что делает:
Мемоизирует результат вычисления.

const sortedList = useMemo(() => heavySort(data), [data]);

Зачем:

избегает дорогих вычислений на каждом рендере

Когда нужен:

expensive computations (фильтрация, сортировка)
стабилизация объектов/массивов

useLayoutEffect()

Что делает:
Синхронный эффект, выполняется:
👉 после DOM-изменений, но ДО отрисовки браузером

useLayoutEffect(() => {
  measureDOM();
});

Зачем:

измерение layout (width, height)
синхронные DOM-изменения без "мигания"

Пример:

tooltip positioning
scroll корректировки
